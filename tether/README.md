# Sony Bridge: ให้เว็บกดชัตเตอร์กล้องจริง

โปรแกรมเล็ก ๆ ที่รันบนเครื่องตู้ถ่ายรูป ทำหน้าที่ตัวกลางระหว่างเว็บกับกล้อง Sony ที่ต่อผ่าน USB
- เว็บนับถอยหลังเหมือนเดิม พอถึง 0 จะสั่งให้โปรแกรมนี้กด**ชัตเตอร์จริง**ของกล้อง
- โปรแกรมดึงไฟล์ JPEG **เต็มความละเอียด** (a7C = 6000×4000) มาให้เว็บใส่กรอบ
- ต้นฉบับทุกรูปเก็บไว้ที่ `~/Pictures/PhotoBooth-Sony`

ถ้าโปรแกรมไม่ได้เปิด หรือดึงรูปไม่สำเร็จ เว็บจะใช้ภาพจากกล้องปกติแทนเอง งานไม่สะดุด

```
 [กล้อง a7C] ──USB──▶ [Sony Bridge :5123] ◀──▶ [เว็บใน Chrome]
      └──HDMI──▶ [capture card] ───────────────▶ ภาพสดสำหรับจัดท่า (แนะนำ)
```

## ใครใช้แบบไหน

| เครื่อง | ใช้ได้แค่ไหน |
|---|---|
| **Mac** (เครื่องวันงาน) | กล้องจริงผ่าน gphoto2 |
| **Linux** | กล้องจริงผ่าน gphoto2 |
| **Windows** | โหมดทดสอบ (`mock`) เพื่อลองหน้าเว็บ ส่วนกล้องจริงยังไม่รองรับ (ดูหัวข้อท้ายไฟล์) |

ต้องมี **Node.js 18 ขึ้นไป** (ถ้าเครื่องรันเว็บนี้ได้อยู่แล้วก็มีแล้ว)

---

## 1. ทดสอบหน้าเว็บโดยไม่มีกล้อง (ทุกเครื่อง รวม Windows)

```bash
npm run bridge:mock
```

1. เปิดเว็บใน Chrome (เว็บจริงบน Vercel หรือ `npm run dev`)
2. เลือกกรอบ ไปหน้าถ่ายรูป แล้วกดปุ่ม **(i)** ข้างตัวเลือกกล้อง
3. ติ๊ก **ใช้ Sony Bridge** ถ้า Chrome ถามว่า *อนุญาตให้เข้าถึงอุปกรณ์ในเครือข่าย* ให้กด **Allow**
4. ปิดหน้าต่าง จะเห็นกล่องสถานะสีเขียวว่า "ถ่ายด้วยชัตเตอร์กล้องจริง · Mock camera"
5. กดเริ่มถ่าย รูปที่ได้จะเป็นภาพทดสอบ "MOCK SONY" แปลว่าระบบทำงานครบทั้งเส้นทาง

## 2. ใช้กับกล้องจริงบน Mac

### ติดตั้งครั้งแรก
```bash
# ถ้ายังไม่มี Homebrew: https://brew.sh
brew install gphoto2 node
```

### ตั้งกล้อง a7C
1. ปิด Imaging Edge Webcam / Desktop / Remote ให้หมด เพราะใช้ USB แย่งกัน
2. หมุน dial ไป**โหมดภาพนิ่ง** (P หรือ A หรือ M) ห้ามใช้โหมดวิดีโอ
3. MENU → **USB Connection** → **PC Remote**
4. MENU → **PC Remote Function** (ถ้ามี) → Still Img. Save Dest. → **PC Only** หรือ **PC+Camera**
5. **Quality / File Format** → **JPEG** หรือ RAW+JPEG (ถ้าเลือก RAW อย่างเดียว เว็บจะไม่ได้รูป)
6. ปิด Auto Power Off (Power Save Start Time → 30 Min หรือ Off) และใช้**แบตเตอรี่ดัมมี่เสียบไฟบ้าน**
7. เสียบสาย USB เข้า Mac

### เช็กว่า gphoto2 เห็นกล้อง
```bash
gphoto2 --auto-detect                  # ต้องเห็นบรรทัด Sony ...
gphoto2 --capture-image-and-download   # กล้องต้องลั่นชัตเตอร์ และได้ไฟล์ .jpg
```
ถ้าขึ้น `Could not claim the USB device` ให้รัน `killall -9 ptpcamerad` (macOS แย่งกล้องไป) แล้วลองใหม่ Bridge จะสั่งคำสั่งนี้ให้เองอัตโนมัติ

### เปิด Bridge
```bash
npm run bridge
```
ข้อความควรขึ้นว่า `พบกล้อง: Sony Alpha-A7C ...` จากนั้นเปิดใช้ในเว็บแบบเดียวกับข้อ 1

### ภาพสดสำหรับจัดท่า
- **แบบแนะนำ: HDMI capture card**
  - ภาพลื่น 30 fps เลือกกล้องในเว็บเป็นตัว capture card
  - ตั้ง HDMI Info. Display บนกล้องเป็น **Off**
  - กล้องต้องอยู่**โหมดภาพนิ่ง** กรอบภาพสดจึงจะตรงกับรูปจริง
- **แบบไม่มี capture card**
  - เลือกกล้องในเว็บเป็น **"Sony · ภาพสดจากโปรแกรมตัวกลาง"** (ภาพสดผ่าน USB จาก gphoto2)
  - ข้อเสีย: ภาพหยาบกว่า และภาพสดจะหยุดประมาณ 1–2 วินาทีทุกครั้งที่ถ่าย

### ตอนถ่าย
นับถึง 0 แล้วจอจะขึ้น **"ค้างท่าไว้…"** ระหว่างกล้องถ่ายและส่งไฟล์ (ประมาณ 1–3 วินาที) แล้วจึงแฟลช

## 3. ตัวเลือกเพิ่มเติม
```bash
node tether/sony-bridge.mjs --help
node tether/sony-bridge.mjs --dir ~/Desktop/booth-photos      # เปลี่ยนที่เก็บต้นฉบับ
node tether/sony-bridge.mjs --allow-origin https://my-preview.vercel.app   # อนุญาตเว็บอื่น
```
- Bridge รับคำสั่งเฉพาะจากในเครื่องตัวเอง (127.0.0.1)
- รับเฉพาะจากเว็บ `photobooth-tdfb.vercel.app` และ `localhost` เว็บอื่นจะถูกปฏิเสธ (403)
- เปิด `http://127.0.0.1:5123` ใน browser เพื่อดูสถานะและภาพสดของ Bridge เองได้

## API (สำหรับนักพัฒนา)
| คำสั่ง | ผลลัพธ์ |
|---|---|
| `GET /status` | `{ ok, version, backend, camera, ready, busy, liveview }` |
| `POST /capture` | สั่งถ่าย → `{ ok, id, url, bytes, ms }` |
| `GET /photos/<file>.jpg` | ไฟล์รูปเต็ม |
| `GET /liveview` | MJPEG (`multipart/x-mixed-replace`) |

ฝั่งเว็บ: `src/lib/tether.ts`, `src/hooks/useTether.ts`

## สิ่งที่ยังไม่ได้ทดสอบ / ทำต่อ
- **ยังไม่ได้ลองกับ a7C ตัวจริง** ทดสอบแล้วเฉพาะโหมดจำลอง ต้องเช็กบน Mac ตามข้อ 2 ว่า `gphoto2 --auto-detect` เห็นกล้องและถ่ายได้
- **Windows กับกล้องจริง** มี 2 ทาง:
  1. เขียน backend ใหม่ด้วย Sony Camera Remote SDK (C++) ให้ตอบ API เดียวกัน (ต้องเช็กก่อนว่า SDK รองรับ ILCE-7C)
  2. ใช้ WSL2 + usbipd ส่ง USB เข้า Linux แล้วรัน gphoto2 (ทางสำหรับผู้เชี่ยวชาญ)

  ทั้งสองทาง ฝั่งเว็บไม่ต้องแก้ เพราะคุยผ่าน API เดียวกัน
